current commitment under an approved native plan. It contains no identity,
credential, endpoint, tool override, goal/run/budget or permission. The loop
uses actual authenticated owner context and configured verified actors, current
source/plan/charter/resource admission and exact recorded owner decisions.

An owner decision records approval, scheduled=false. Tick resolves the actual
actor and fully recomputes current report/check bytes, target and recipe/hash/
input pins before consuming approval in the same CompanyControl transaction as
the existing M1 held reservation. After awaited hold/provenance reads it rechecks
current exact authority and every source/recipient/profile/approval deadline.
Expiry rolls back consumption and cost. Native scheduler enqueues just this task;
tick never starts a worker or issues an effect itself.

Actual author receipt permits an actual independent verifier claim/preparation,
then await_approval releases capacity before another owner decision. Approved
check dispatch uses the existing native worker/protected acceptance. Pending and
accepted ticks create no new actions, effects, charges, runs or model requests.

the same pending wait; live peer capacity is untouched. Historical noncurrent
acceptance cannot become replacement work.
