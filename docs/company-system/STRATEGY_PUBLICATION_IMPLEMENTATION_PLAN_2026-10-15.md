# Strategy publication implementation boundaries

Source plan following the accepted StrategyBrief ABI. Pure description/check and
separate strategy action identity slices are being qualified. No worker, mixed
plan, protected publication, acceptance or owner-choice transition is activated.

The next coherent slice must make S/SV output native and independently checked.
Keep original producing inputs separate from current authority: the original
`StrategyCheckSnapshot` hash includes observed_at and source heads. Never rebuild
that snapshot with a verifier's new clock or revision2 plan. Preserve its exact
original bytes and separately revalidate all current sources/grants/governance
against the fresh DB clock. Stored snapshots remain descriptions, not authority.

The next pure compiler accepts `build_strategy_brief(snapshot, policy)` with an
explicit immutable server narrative policy: exact scope/candidate-policy digests,
finding selectors, labelled hypotheses, both candidate narratives, recommendation,
unknowns and owner question. It invents no default business facts. A compiled
wrapper retains the original protected input-bundle reference separately; its
prepared manifest stays exactly `snapshot.inputs`, matching the brief's original
manifest hash. Before publication, the real publisher must prove and persist the
bundle linkage/complete privacy closure separately. This unresolved native step
cannot be replaced by a descriptive bundle ref or silently omitted for activation.

1. Add a protected strategy-input bundle containing the immutable original
   snapshot and byte hash. Prepare bounded actual source/evidence bytes outside
   the company mutex; resolve exact actual current S/SV registrations/edge and
   original revision1 plan under the mutex. Resolve the finite candidate policy
   from trusted server configuration and protected source manifest, never action
   parameters or a model-produced policy. Reuse native manifest and paged protected
   byte primitives only where their complete provenance semantics match.
2. Add a deterministic producer over the full typed snapshot: exact quotation
   findings, separately labelled hypotheses/expectations, reviewed change/defer
   alternatives, tradeoffs, recommendation, explicit unknowns/deployed limits and
   owner decision request. Persist its original input bundle with protected
   derivation lineage; an optional future LLM draft needs its actual governed
   result, not a new call during revalidation. Deterministic mechanical output
   alone cannot qualify LLM quality or strategic merit.
3. Add a strategy-only two-phase publisher. Check actual current registered actor,
   action/tool/target, issued intent/fence and sealed credential; recompute exact
   bytes/manifest from the actual immutable bundle; prepare blob outside locks;
   reacquire company-first transaction; repeat all checks and compare both initial
   and current audiences. After every awaited write/lookup, take the actual DB
   clock and synchronously check source/grant/lease/approval/profile/credential
   deadlines before commit. Preserve immutable replay bytes/edges and unknown
   billing. Do not stretch GeneratedTool/report selectors or mint authority.
4. Add independent SV check publication and native acceptance using its actual
   succeeded receipt and protected result, complete current inputs, exact unique
   author/verifier pair and original target hashes. A raw passing result or
   artifact file cannot accept work. Unsupported criteria remain inconclusive.
5. Integrate the separately reviewed owner-choice seam. Optional typed strategy
   selection is excluded when absent. Revision2's actual signed owner decision
   binds brief/acceptance/candidate/scope hash. A concrete protected transition
   reader must re-resolve original S/SV proof after staged head2 writes and final
   flush, prove complete immutable partition, and recheck every deadline with the
   actual sealed request-identity witness. Absent witness/reader denies transition.

Split work across the existing small team: source input/producer, protected
publisher/check/acceptance, and Root-owned plan/API/runtime seams. Review at these
boundaries; no review-per-edit requirement. Keep new modules below400 lines and
functions below50 unless a concrete cohesive-boundary rationale is recorded.

Before runtime integration, freeze one exclusive normal015 PostgreSQL packet
with actual public stores and no structural acceptance bypass. Prove original
S/SV acceptance, unchanged provenance through owner-selected revision2, exact
permanent quotas and post-await expiry/revocation rollback. Then qualify durable
replay and an actual StockFlow goal. Pure fixtures and source plans establish
neither SQL correctness nor a running autonomous company.
