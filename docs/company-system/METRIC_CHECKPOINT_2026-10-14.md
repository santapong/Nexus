# Native measured outcomes checkpoint

Native `native.accepted-report-count.v1` measures actual current independently
accepted reports under an exact approved goal/plan and selected work. Raw
candidates and genuine absent acceptance count zero; private, unsupported or
stale proof becomes unknown. Baseline unknown stays unknown. Observations do not
complete goals, issue work, consume new allowances or authorize actions.

The owner API publishes immutable observations, serves permission-qualified
dated history and freshly derives current readings. Current discovery is one
owner mutex transaction with max8 items, native date/UUID cursor,30s bound and
2MiB representation. All captured source/baseline/grant deadlines are checked
after the final awaited page read. Exact replay binds owner, operation, audit,
request and native snapshot. Missing records return404; default services stay
unconfigured. Explicit disposable pilot composition supplies the native stores.

Dashboard plan/goal views now support explicit bounded work selection, retained
request IDs for uncertain retries and durable observation discovery. Current
check time, original record time, source event precision and ingestion time are
distinct. Dated history is reauthorized before display. Unknown never appears
as zero; target satisfaction is limited to the selected work. Only the first8
support source dates render inline when the complete server set is larger.
