# M2 Company Brain implementation plan

**Prepared:** 2026-10-14, Asia/Bangkok. **Status:** proposed implementation packages; no M2 runtime acceptance yet. **Scope:** [SDD §§7–8](../sdd/NEXUS_SDD_v0.2.md#7-ontology-and-company-brain), [M2 gate](IMPLEMENTATION_PLAN.md#m2--build-the-evidence-backed-company-brain), [M0–M6 release plan](RELEASE_EXECUTION_PLAN.md). Preserve the supervised internal-company direction, US$5/day, registered lifetime work allowances, and deferred Meta Harness.

## Evidence and definition of done

The existing [knowledge contracts](../../backend/nexus/company/contracts/knowledge.py) validate company IDs, explicit source access lists and citation presence. [Context tests](../../backend/nexus/tests/unit/test_company_context.py) validate references and fixture integrity. Neither establishes persistent retrieval, current ACL enforcement, actual prompt inclusion, current source-system truth, or independent business completion. A `verification_id` alone is not proof that its referenced verification exists or passed.

M2 is done when immutable provenance and typed relationships persist through the independent company migration lineage; current permissions gate search, context and derivatives; source changes invalidate relevant action preconditions; attachments/workspace content reaches the actual request; and the frozen 30 questions pass **at least 27/30 and every one of the 16 critical cases**. Record real-source acceptance separately from synthetic acceptance. M1 integration remains a prerequisite for enabling model-backed ingestion or production context use.

This document changes no code, schema, fixture, data or activation setting. Package ownership and interfaces must be agreed before implementation. Root retains shared contract, migration, authority and runtime integration ownership.

## Storage and ontology

Use PostgreSQL with SQLAlchemy async services, strict versioned Pydantic boundaries and the existing company profile. No Neo4j, Graphiti, separate vector service or new event bus. Keep immutable historical records separate from mutable current pointers, access state and availability. All keys/FKs include native UUID `company_id`; referenced revisions use composite company/identity/revision keys. Never import legacy IDs, JWT roles or nullable workspace ownership as authority.

Proposed tables below are a schema review list, not an applied migration. Root selects the next company migration number after M1 stabilizes.

| Record/table family | Immutable content and constraints |
| --- | --- |
| `company_brain_sources` / `company_brain_source_revisions` | Stable source identity; registered server-owned source-system symbol and external identity; immutable revision, raw artifact, author, event time/date precision, server ingestion time, source-provided revision/ETag/commit, availability/freshness evidence. Current revision pointer uses compare-and-swap. Same external revision with different bytes is a conflict, never an overwrite. |
| `company_brain_artifact_revisions` | Artifact ID/revision, SHA-256, byte count, MIME type, server-owned storage reference, creating action/receipt if applicable. Addressing is company scoped even for identical hashes. No caller filesystem path, arbitrary URL fetch or global hash lookup. |
| `company_brain_parse_revisions` / `company_brain_chunks` | Source/artifact revision, parser/chunker version, canonical text hash, section/path/page locator and UTF-8 byte offsets. Deterministic chunks and stored `tsvector` retain positions. Parse failure is quarantined; raw bytes and previous good revisions survive. |
| `company_brain_entities` / `company_brain_entity_revisions` | Stable typed identity and append-only validated fields. Schema version, author/origin, evidence and effective interval accompany each revision. Existing directory/work/action/budget IDs are references to their authoritative stores, not copied writable execution state. |
| `company_brain_relationship_revisions` | Registered predicate and allowed endpoint types/revisions, effective interval, origin, evidence, proposed/accepted status. Foreign or missing endpoints fail. Arbitrary extracted predicates never become executable edges. |
| `company_brain_claim_revisions` / `company_brain_claim_evidence` | Stable claim/revision; one of the six claim kinds; bounded text, subject/entity references, source author/origin, event/ingestion/validity metadata; evidence links marked supports/challenges. Observation/outcome publication requires supporting evidence. |
| `company_brain_evidence` | Exact source/artifact/parse revision and bounded locator/span/hash; evidence purpose and derivation references. Citations resolve to these immutable bytes, not a changing URL. Evidence may also reference a real immutable receipt/verification record. |
| `company_brain_claim_links` | Explicit conflicts-with/supersedes links between exact claim revisions plus rationale, author and evidence. No self-link, cross-company link or supersession cycle. Conflict resolution is a new record; both histories remain. |
| `company_brain_resource_access` / `company_brain_access_events` | Current owner-managed resource/principal read grant with generation, activity and expiry; immutable grant/revoke history. Principal FK points to current company membership. Source-derived content inherits all contributing resource restrictions. |
| `company_brain_derivations` | Summary/presentation/context artifact revision and all contributing source/evidence revisions; recipe/model/prompt versions if used. Derivative readership cannot exceed the intersection of contributing resources. |
| `company_brain_events` | Transactional source/ACL/receipt/verification change events; company, event ID, resource/revision, event type, deterministic deduplication key and consumer cursor. No raw source text or credentials in queue/log payloads. |

Mutable pointers/access rows cannot alter revision bytes. Artifact/parse/entity/relationship/claim/evidence/derivation records receive append-only database guards and company RLS. UNIQUE constraints cover source symbol/external identity/revision and parser/chunker configuration; indexes cover company/source/revision, predicates/endpoints, principal/resource grants, claim kind/subject and event cursor. Source revisions and claims retain unknown dates explicitly; do not fabricate event timestamps from ingestion time. Store UTC instants and original date/time precision; Bangkok remains the budgeting/reporting timezone.

Entity kinds are Company, Department, Principal, Product, Project, Goal, WorkItem, Customer, SupportCase, Decision, Commitment, Evidence, Artifact, Action, Verification, Budget and AuthorityPolicy. Implement a closed endpoint matrix first: Company has Department; Department owns Goal; Project supports Goal; Product has SupportCase; Customer reports SupportCase; SupportCase concerns Product; Decision cites Evidence; Commitment supports Goal; WorkItem produces Artifact; Action has Receipt/Verification references; Evidence supports/challenges Claim. Domain references resolve to real same-company records. Knowledge traversal never creates work DAG dependencies, permissions, counters or completed states; those remain with their authoritative M1/M3 contracts.

### Claim publication rules

| Kind | Required treatment |
| --- | --- |
| `observation` | Evidence supports the stated observation; report whether it is source-reported, directly measured or currently confirmed. A customer statement is evidence of a report, not automatic proof of product behavior. |
| `decision` | Identify who decided, when, under which mandate/policy, and the supporting source/decision record. A model's suggested decision remains proposed. |
| `hypothesis` | Explicitly uncertain; distinguish supporting/challenging evidence. Confidence never substitutes for verification. |
| `plan` | Proposed/intended work with relevant dates and blockers. Creating or finishing a plan document does not complete its work. |
| `commitment` | Record the source of the promise, recipient and due date separately from work status. A proposed message cannot create an externally made commitment. |
| `verified_outcome` | Trusted publisher resolves actual receipt, independent verification, exact action/criteria, evidence hashes and scope. Known success and full acceptance are required for the stated outcome. A verification candidate, timeout, exception, unknown effect or owner approval alone fails. |

Extraction returns only bounded proposed claims/relationships. Its schema excludes `verified_outcome`, completed work, authority grants and source-authority changes. Trusted publication validates real foreign records; model-supplied UUIDs cannot mint proof. Brain ingestion cannot mutate work completion. Until a real independent completion publisher exists, outcome promotion stays unavailable; M2 negative tests can prove rejection without claiming the M4/M5 business verifier is delivered.

Newest ingestion does not decide truth. Select current authoritative source revisions according to the registered source policy and effective/event dates. Equal-authority contradictions remain unresolved with both citations. Supersession needs explicit source/owner resolution, preserves history and does not silently resolve unrelated conflicts. If part of a conflict is inaccessible, return only authorized evidence with an uncertainty limitation; do not expose the hidden source's identity or contents.

## Permission and freshness boundaries

Read scope is server derived from `VerifiedIdentity`, current workspace/company mapping and current membership. Company-wide Brain reads use a distinct operation audit ID, with no work budget. Work-linked reads/context additionally require registered task/trace, actual actor/current owner and the current work policy. Owner audit can read correctly scoped inactive work according to existing M1 rules; owner status alone does not bypass a restricted source grant. Initial grants explicitly include intended readers.

Every SQL query applies company and current resource ACL constraints before rank, snippets, totals or traversal. RLS provides a second boundary. Table-owner/superuser/BYPASSRLS connections are forbidden for application retrieval; PostgreSQL documents their bypass behavior, policy evaluation and foreign-key error leakage. Use parameterized queries and generic absent/denied responses rather than exposing foreign-row constraint details. [PostgreSQL row security](https://www.postgresql.org/docs/16/ddl-rowsecurity.html).

Use short transactions with **CompanyControl first** for ACL mutations and final materialization. Under that lock, re-read mapping/membership, ACL activity/expiry, source heads and all derivation contributors; do not trust earlier `allowed_principals` snapshots or JWT role fields. Commit before parsing/model/network work. PostgreSQL warns that policies consulting other tables can race with permission updates; combined two-session tests must prove our lock order and materialization boundary. [PostgreSQL permission races](https://www.postgresql.org/docs/16/ddl-rowsecurity.html).

Candidate search results are opaque handles until materialized. Cache keys include company/principal, ACL generation, source revision, parser/retrieval configuration and purpose; a cache hit still rechecks live access. Logs, counts, graph endpoints, citation resolution, artifact downloads and export rendering use the same check. A summary whose contributing resource was revoked is unavailable until rebuilt from authorized inputs; remove the whole derivative rather than assume safe redaction. No inaccessible-source summary, embedding content, prompt, chart or recipient can escape through a less restricted output.

Context is revalidated at the actual model call claim, and again before publishing its answer/derivative. Revalidate under the trusted M1 authorizer transaction; no client permit or independently supplied ACL snapshot. A revocation committed before claim prevents issuance. A revocation after an already issued request cannot undo provider disclosure; it prevents subsequent reuse/publication. Never hold a database lock across model I/O.

Source snapshots are cached observations, not the live source system. Registered resolvers return current revision/freshness proof from the authoritative system or an explicit unknown/unavailable result; no result means action conflict. For local nominated Git sources, the commit plus selected blob hashes is authoritative for that snapshot only, not production deployment. Volatile external values require a fresh governed resolver at the effect boundary. This plan enables no external connector.

Include all action-relevant source heads, ACL generation and policy revisions as server-generated `ResourceRevision` preconditions in the existing canonical `ActionProposal`. Approval/hash binding and effect recheck use these resources. Changed head, expired freshness, unresolved action-relevant conflict, revoked access or unavailable resolver returns `409`/typed conflict for replanning; old approval cannot authorize changed inputs. Source updates must not mutate an authorized proposal or blindly retry an unknown external effect. For external state-sensitive writes, enforce the source revision through the provider's conditional mutation where supported; a local refresh cannot prevent a later remote change. An unsupported conditional-write boundary remains an explicit effect/tool activation limitation.

## Retrieval and actual context

Start with **`brain-retrieval-v1`: permission-filtered FTS plus typed relationships**, without embeddings or model reranking. PostgreSQL supports `tsvector`/`tsquery`, positional `ts_rank_cd`, and GIN text indexes. Choose a registered text configuration explicitly, use parameterized `websearch_to_tsquery`, store its version, and retain stable UUID/revision tie-breaks. Rank is relevance, not truth/confidence. [PostgreSQL text search](https://www.postgresql.org/docs/16/textsearch-controls.html), [GIN indexes](https://www.postgresql.org/docs/16/textsearch-indexes.html).

Retrieval sequence:

1. Validate signed identity/current scope and bounded query/entity filters. Select authorized current source revisions or an explicit authorized historical revision; apply claim-kind/validity filters before ranking. No unfiltered candidate list handed to an LLM.
2. Retrieve exact identifiers/direct entity matches and FTS matches; expand only registered predicates through at most two hops. Recheck each node/edge and all evidence contributors. Bring supporting/challenging/supersession evidence into the candidate set under the same access rules.
3. Deduplicate exact source/chunk/revision handles. Use a documented lexicographic order: explicit requested evidence, action/acceptance dependency, exact entity match, relationship hop, FTS rank descending, stable source/revision/chunk ID. Cap candidates before materialization; manifest reports authorized omissions.
4. Materialize current allowed content in a short locked transaction. Resolve citations and provenance chains; no missing-support observation or unresolved revision enters the factual answer set. Keep authorized conflicts/hypotheses visible with their labels.
5. Assemble shared context and render the exact model request. Persist the manifest/prompt hash as a restricted artifact, and capture the real offline SDK request in tests. A list of references alone does not satisfy B13/B14.

Thai and mixed-language sources need a measured tokenizer/search configuration rather than an English stemming assumption. Initially report unsupported search language/configuration and retain explicit entity/section retrieval; freeze representative real-source tests before claiming Thai semantic search. No new framework is selected on that gap alone.

Future optional vectors store chunk hash/revision, embedding provider/model exact ID, dimension, distance metric, tokenizer/normalization, embedding recipe and price versions. Model/version/dimension changes create a new index namespace, never mix vectors. Default disabled; any paid embedding needs the M1 per-request reservation/counter/data-policy gate. First compare exact search within an already authorized candidate set with the FTS baseline. pgvector documents exact search and the recall tradeoff of approximate indexes; ANN filtering occurs after index scanning. Therefore shared ANN cannot be presented as prefiltered permission retrieval. Require tenant/ACL-safe design, frozen recall/denial tests and measured need before enabling ANN or another graph engine. [Official pgvector documentation](https://github.com/pgvector/pgvector#filtering).

### Versioned interfaces to freeze before coding

New Brain boundaries use `nexus.company.brain.v1`, strict immutable typed fields and bounded tuples/text. Preserve existing `nexus.company.v1` wire meaning; extend by explicit new contracts/adapters rather than silently changing their ACL or completion semantics.

| Interface | Inputs → outputs; authority |
| --- | --- |
| `BrainReadScope` | Server-derived company/workspace/principal/operation/trace and optional registered task binding. A read scope cannot reserve or mint work budget. |
| `SourceRegistration`, `IngestCommand`, `IngestReceipt` | Registered source symbol, expected previous revision, immutable nominated artifact, parser configuration → accepted/quarantined/conflict revision receipt. ACLs and source authority are resolved server side. |
| `SourceResolver.current(...)` | Exact registered resource plus trusted scope → current revision/freshness proof or unavailable. External access requires its own governed tool registration. |
| `ClaimCandidateBatch`, `publish_claims(...)` | Proposed evidence-bound extraction/manual records → immutable accepted/proposed revisions after semantic/reference/access validation. Caller cannot publish verified outcomes or change authority. |
| `publish_verified_outcome(...)` | Trusted publisher plus actual ledger/verification references → scoped outcome revision or rejection. No public model-facing promotion endpoint. |
| `BrainRetriever.search(scope, query, limits)` | Current authorized scope, versioned query/filter → bounded citation handles/ranking manifest. `materialize(scope, handles)` revalidates all current ACL/source contributors. |
| `ContextAssembler.assemble(identity, registered_scope, request)` | Server policy/mandate/charter/work/acceptance/feedback and authorized source selection → `AssembledContext` containing a new bundle, immutable inclusion/omission/staleness manifest and rendered prompt/hash. |
| `revalidate_context(session, scope, manifest)` | Existing locked M1 claim/effect transaction → current resource preconditions or denied/stale/conflict. Does not open/commit another transaction or issue a provider call. |
| Evidence read API | Current signed identity plus opaque same-company IDs/revisions → typed search/entity/evidence/artifact/freshness results only after final materialization checks. `403`/generic absence for denial, `409` for stale revisions, `422` for schema bounds. No arbitrary SQL/path/URL or extraction bypass. |

`AssembledContext` includes mandate and goal ancestry, charter, exact work/attempt/trace, acceptance criteria, policy/budget/authority versions, verifier feedback, cited dated claims, selected attachment/workspace text and artifact handles. Each included part has role/purpose, source/parse/chunk/revision/hash, bounded locator, provenance contributors and token allocation. Manifest entries distinguish included, excerpted, summarized, omitted and stale; unauthorized IDs/content are never listed as omission details. Derived summaries retain their complete provenance chain.

Mandatory authority/work instructions precede acceptance/feedback, then evidence, selected attachments/workspace excerpts. Source text is clearly delimited untrusted data; instructions inside it cannot change role, budget, tools or mandate. All departments use this assembler. Missing mandatory acceptance/work/policy parts fail assembly; evidence truncation remains explicit with authorized bounded follow-up reads. Token counting includes rendered system/user text, schema/tool definitions and SDK framing for the registered model/API family. Unknown token accounting fails closed; character length is only a byte/processing guard.

Proposed configurable upper bounds for the first package: 2 MiB source bytes; 1 MiB canonical parsed text; 10-second isolated parse timeout; 8 KiB/chunk and 256 chunks/source revision; 2,000-byte query; 100 candidates, 20 returned evidence spans, two relationship hops/200 edges; 32 contributing resources and 16 derivation levels; 64 KiB total materialized evidence; 16 KiB/span; 2-second SQL statement timeout. Reject oversized/unsupported inputs before expensive work; never silently mark partial ingestion complete. Context limits are mandatory server-owned policy. Read-only rendering enforces exact byte/span/section bounds and reports token qualification unavailable until a qualified recipe exists. WorkItem currently records USD and attempt limits, not an aggregate token allocation; do not invent one from caller max_tokens. Model use requires a qualified estimator/profile/recipe covering the full rendered input, schemas and SDK framing under the M1 claim; its ceiling comes from the registered model/window and exact owner-approved input/output bounds and current USD reservation. Initial ingestion supports declared UTF-8 text/Markdown/JSON and nominated Git files; unsupported binary/archives fail explicitly. Measure these proposed limits on the first real pack before activation, without relaxing security rubrics.

## Event-driven updates and crash behavior

Source revision, ACL revocation, receipt and accepted verification changes write an outbox event in the same company transaction as their state change. A bounded existing DBOS consumer processes immutable events idempotently by company/event/recipe; checkpoints never reset lifetime work counters. Source replacement uses compare-and-swap, keeps old bytes, reparses changed content and marks dependent claims/derivatives stale. ACL events invalidate reuse immediately through current checks even if cache invalidation lags. Outbox lag cannot make an old source fresh.

Parsing/retrieval/invalidation is deterministic and incurs no model calls while idle. Model extraction is an optional separately registered work action using the M1 model-per-request gate; an event cannot create authority or replenish allowance. A nominated source change signals affected registered work for explicit reassembly/replanning, not automatic execution of changed actions. Unknown effects remain with owner reconciliation.

Persist and hash immutable blob bytes before committing their database references; verify them on read. A crash can leave an unreferenced blob, not a committed reference to missing content. Bounded orphan cleanup observes a retention/grace policy and never deletes cited historical evidence implicitly. Consumer crash before/after parse/event acknowledgment produces the same revision/claim set without duplicate publication. Connector polling/webhooks, external customer state and retention/erasure policy are separately configured integration work, not activated by M2 planning.

## Packages, sequence and review

Keep the existing M2 estimate **6–9 engineering days** as a planning baseline, not elapsed-time evidence. Parallelize after shared schema/interfaces freeze; migration/ACL/prompt integration remains the critical path. Do not divide the estimate by the number of agents.

| Package/owner lane | Concrete deliverable | Required verification before handoff |
