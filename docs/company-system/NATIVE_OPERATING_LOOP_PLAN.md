# Bounded native operating loop

One trusted, reloadable NativeOperatingRegistration binds one existing exact
owner-saved report/profile/current commitment. Native references and file hashes
are selectors/integrity checks, not owner or registration authority. Root accepted
this no-DDL interpretation on 2026-10-14. No new goal, report, task, run, budget,
standing grant or model call is created by registration or an idle tick.

`save_native_operating_registration(path, registration)` saves bounded immutable
server configuration; exact retries are idempotent and changed-byte overwrite is
denied. `load_native_operating_registration(path)` strictly restores it. These are
operator-side files containing no identities, credentials, endpoints or permits.

`NativeReportOperatingLoop(registration, preparation, native)` composes the actual
preparer, M1 stores and ManagementScheduler with the native workflow registration.
`tick(actual_owner_scope, actual_verified_owner_identity, event=None)` reads fresh
native facts under current owner CompanyControl. It uses an exact native EventWake
when supplied; otherwise it derives the current minute bucket from DB time. There
is no timer or trusted identity fabricated from CompanyControl.owner_id. The
caller/explicit trusted issuer must perform actual authentication and token
expiry checks before producing VerifiedIdentity; that existing DTO contains
only verified principal/workspace and no serialized signature/expiry/owner flag.
Tick rechecks actual current directory owner/membership under the company mutex.

The first due tick prepares one pending author action. Pending decisions idle.
An existing exact HTTP owner approval is consumed only by the configured actual
actor under CompanyControl. Full native target/report/check bytes, recipe/hashes,
current resources, plan/goal/charter and complete source/recipient protection are
rederived before and after the actual cost-hold flush. Fresh final approval,
grant/source/profile deadlines roll back consumption/hold on expiry. The existing
M1 budget/lifetime logic is shared through a narrow public same-session extraction.
Only an actually authorized action reaches the existing scheduler for its
registered task; scheduler/worker retain fresh authorization and permanent
dispatch checks. The loop never approves or runs the worker.
After the actual successful author receipt, one actual selected verifier claim
prepares its pending check, then await_approval releases capacity before waiting
for an owner decision. An expired unissued preparation lease can be reacquired
through the actual current M1 claim gate solely to enter that same pending wait;
live peer capacity and unknown deadlines are not replaced. Approval/authorization
then permits exact check dispatch;
the existing native worker independently produces its protected acceptance.
Current acceptance closes this finite saved occurrence. Unknown/issued outcomes
retain native receipts, holds and reconciliation-only dispatch; no fresh retry or
render is inferred from missing output. Historical noncurrent acceptance is not
reclassified as never issued, and no replacement draft is generated.

Minute fallback bounds discovery of action decisions/membership and other changes
without native events. An opportunity scan every 15 minutes only examines
this same owner-approved registration; it cannot invent another occurrence or
propose work outside its exact owner configuration. Every tick can read current
status without invoking an LLM. The public read_registered_verification_target
selector reuses exact native target logic with actual signed registered verifier,
work/receipt/artifact and qualified source checks. It constructs no lease. Existing
resolve_target/resolve_native_target preserve their execute/mode/fence gates.

New registration activation, authenticated timer
issuer, production worker launch, owner UI/API and external/provider/device work
remain Root integration/explicit operation work.

Focused proof will use a new exclusively assigned operating_loop database with
normal company migrations and the restricted application role. It will cover actual
author/check dispatch and public native worker receipts/acceptance, config reload,
pending/complete idle conservation, verifier capacity release, foreign/missing
current mapping, current pause/cancellation/plan/source revocation, exact selectors
and issued unknown preservation. Two separately approved narrow shared extractions
cover journal authorization and lease-independent native target materialization.
The source-frozen preparer, M1 store behavior, schema and API remain unchanged.
